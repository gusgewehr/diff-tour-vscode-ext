src/pick.ts:

Types: `Entry` union:
- { kind: 'change'; candidate: Candidate; target?: Target; error?: string }
- { kind: 'saved'; path: string; label: string; files?: number }
- { kind: 'commit' } | { kind: 'range' } | { kind: 'file' }
- { kind: 'info'; label: string } (not pickable)
`Group` { id: 'compare' | 'prs' | 'saved' | 'other'; label: string; entries: Entry[] }.

`Deps` passed in by extension.ts: { settings(): Settings; savedDir: string; extensionPath: string }.

`class ChangeModel` (shared by QuickPick and tree, so both show the same groups per PICK-05):
- fields: groups: Group[], cwd?: string, message?: string, counting: boolean, private gen counter, `onDidChange` from a vscode.EventEmitter<void>.
- `refresh()`: bump gen; cwd = repoRoot(first workspace folder fsPath) (shortcut comment: multi-root uses the first folder; upgrade when multi-root repos matter); no folder or not a git repo -> groups [] and message `Open a folder that contains a git repository.`, fire, return. Else base = detectBase(cwd, settings.baseBranch) (error -> message = error text, groups []); run compareCandidates, listPrs and listSavedTours in parallel. Build groups in order:
  1. compare: label `COMPARED WITH <base>`; entries = candidates as 'change'; when onBase, prepend info `You are on <base>. Pick another branch, a commit or a range.`
  2. prs: label `REVIEW REQUESTED`, only when listPrs returned items (hidden silently otherwise, PICK-04)
  3. saved: label `SAVED`; saved tours as 'saved', or one info `No saved tours yet` when empty
  4. other: label `OTHER`; entries commit, range, file
  Fire onDidChange. Then set counting = true and use mapLimit(branch change entries, 6, ...) (per D: max ~6 concurrent git calls; PR entries are not counted until picked because they need a fetch) to call resolveTarget(cwd, 'branch', label, base, head), storing target or error on the entry and firing onDidChange after each; drop results if gen changed. counting = false and fire at the end.
- `ensureLoaded()`: refresh once if never loaded; returns the in-flight promise.

Presentation helper `present(entry, minFiles)` -> { label, description?, detail?, icon: codicon id } shared with the tree:
- change: icon git-branch (pr: git-pull-request); description = target ? describeCount(target.files, minFiles) : error ? error : pr ? 'counted when picked' : 'counting…'; detail = candidate.detail
- saved: icon bookmark; description `N files · saved` when files known, else `saved`
- commit: `A single commit…` icon git-commit; range: `A range…` icon diff; file: `A saved tour file…` icon file; info: icon info.

`showPicker(model, deps)` (PICK-01..03): `vscode.window.createQuickPick()`; title `diff-tour: Tour a change`; placeholder exactly `A new tour takes 2 to 5 minutes. A saved tour opens instantly and costs nothing.` (per D); matchOnDescription true. Build items from model.groups: a `QuickPickItemKind.Separator` item per group label, then one item per entry with label `$(<icon>) <label>`, description, detail, and the entry attached. busy = model.counting. Subscribe to model.onDidChange to rebuild items, keep the active item by entry identity, update busy. Call model.refresh() on open. On accept: ignore info entries; otherwise hide and call choose(entry, deps), showing any thrown error via showErrorMessage. Dispose subscriptions on hide.

`choose(entry, deps)` (also registered as difftour.internal.choose):
- change: target = entry.target; if missing (PR or still counting): for pr, c = await fetchPr(cwd, candidate) inside window.withProgress (notification, title `Fetching PR #<n>…`); then resolveTarget(cwd, kind, label, c.base, c.head). Then routeTarget.
- commit: showQuickPick over recentCommits(cwd, 50) items (label subject, description `<sha 7> · <when>`), then resolveTarget(cwd, 'commit', `<sha7> <subject>`, `<sha>^`, sha) (per D, `<sha>^..<sha>`); a root commit fails merge-base -> show `This commit has no parent to compare with.`
- range: showInputBox prompt `Range as <base>..<head>`, validateInput uses parseRange then refExists on both sides, returning a message like `"<ref>" is not a commit in this repository` or `Use <base>..<head>`; then resolveTarget(cwd, 'range', input, base, head).
- file: showOpenDialog { canSelectMany false, filters { 'Tour JSON': ['json'] } } -> executeCommand('difftour.internal.openSavedTour', uri.fsPath).
- saved: executeCommand('difftour.internal.openSavedTour', entry.path).

`routeTarget(target, deps)`: files === 0 -> showInformationMessage `<label>: no changes between <base> and <head>.`; files < settings.minFiles -> executeCommand('difftour.internal.openSmallChange', target) (no CLI needed, per D); else detectTools(settings, roots) where roots = workspace folder paths plus deps.extensionPath; when missing is non-empty -> missingNotice; else executeCommand('difftour.internal.startTour', target).

`missingNotice(missing, deps)` (PICK-07): showErrorMessage with the joined messages and buttons `Open Settings` and `How to install`. Open Settings -> executeCommand('workbench.action.openSettings', 'difftour.cliPath'). How to install -> if `<extensionPath or workspace folder>/cli/FORK.md` exists, executeCommand('vscode.open', Uri.file(it)); else showInformationMessage (modal) with `Build the fork: cd cli && go build -o bin/tour.exe ./cmd/tour, then set difftour.cliPath.` plus the Claude install line when 'claude' is missing.

  - export model-free `deactivate()` that does nothing.

|----------|-------------|
| user input -> git | Range text from the InputBox |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07 | Tampering | range InputBox -> git | mitigate | parseRange rejects `-`-prefixed refs, refExists validates both sides, execFile argv only |
| T-02-08 | Elevation | workspace cli/bin/tour.exe executed by detect | mitigate | Extension does not activate in untrusted workspaces (plan 01 capabilities); cliPath is machine-scoped; execFile with no shell |
| T-02-09 | Spoofing | `where tour` picking a non-fork binary | accept | Only `--version` runs; Phase 4 surfaces protocol errors from a non-fork CLI |
| T-02-10 | Denial of service | hung `--version` / where | mitigate | 5 s timeout on every detection call |
</threat_model>
